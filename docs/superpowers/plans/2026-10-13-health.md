# Local Health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement inline task-by-task.

**Goal:** Persistent local observed journal and shared house-health rules without per-device setup.

**Architecture:** HouseObserver emits sanitized changes into Monitor's bounded pending queue. Monitor uses Storage.db for journal, timers and deduplicated findings; a 10-second task evaluates fresh snapshots. The protected /health endpoint and UI display findings, coverage and journal; chat receives active findings.

**Tech Stack:** Existing Python 3.12 asyncio, SQLite, FastAPI and vanilla JS; no new dependencies.

**Spec:** docs/superpowers/specs/2026-10-13-health-design.md

## Global Constraints
- 14-day retention, maximum 10000 journal records.
- 10-second batch/evaluation interval; clean shutdown flush.
- Battery <20%, recovery >=25%; unavailable/open >=600 seconds.
- Existing approved device and disabled-entity scope and sanitized values only.
- Local UI alerts only; no external notification or HA write.

## Review Focus
- Voltages cannot trigger percentage battery rule.
- Stale/missing states cannot create or resolve device faults.
- Restart preserves pending durations, findings and bounded journal.
- Foreign/removed scope cannot remain in user-visible journal or chat.
- Migration/export freeze stops monitor and flushes before serialization.
